# Старт разработки — бот «Барам»

Бот попутчиков Буинск ⇄ Казань в Telegram (в ТЗ он называется «Попутчики»). Первая версия — **только чат-бот на одном направлении**. Её цель — проверить модель на живых водителях и пассажирах, поэтому делать её нужно быстро и просто.

**Источники:**
- ТЗ: файл проекта «Бот «Попутчики» — техническое задание.pdf». Живая (самая свежая) версия: https://claude.ai/artifact/YFK6oZusqJe4K8Jt3FuzcW
- Макеты экранов: https://claude.ai/artifact/14DahjxvictUGLApB5Trwv (ряд «То же самое в чате бота» относится к версии 1, остальное — к версии 2)

Если ТЗ и этот документ расходятся, для версии 1 главный этот документ.

## Что входит в версию 1

**Регистрация и роли**
- `/start` → «Вы пассажир или водитель?» → «Как вас зовут?» → телефон только кнопкой «Поделиться номером».
- Роли: пассажир, водитель, админ (админы задаются по Telegram ID в настройках).
- Анкета водителя: марка и модель (список + ввод), год, цвет, госномер, число мест, детское кресло да/нет, 2–4 фото машины, фото прав и СТС, реквизиты для предоплаты (номер СБП, банк). Без проверки админом рейсы не публикуются.

**Водитель**
- «Выложить рейс» по шагам: направление, день, время, как забирает (от дома / свои точки / смешанно), деревни да/нет (доплата по договорённости), мест, багажник, цена.
- «Повторить прошлый» — рейс за 2 нажатия.
- «Мои рейсы»: список пассажиров по порядку, звонок, кнопка «Навигатор» (ссылка на Яндекс Карты).
- «+ Занято по телефону» → 1/2/3 места, данные потом по желанию через «Поделиться контактом».
- Кнопки поездки: «Выехал», «Буду через 5 / 10 / 15 / 30 мин», «Забрал», «Доехали». Геолокацию не используем.
- Новая бронь → «Принять» / «Отказать».
- Защита от спама: не больше 2 рейсов в каждую сторону в день, без пересечения по времени, без дублей (±1 час), не дальше 7 дней вперёд.

**Пассажир**
- Поиск по шагам: кто едет (я / другой человек / сохранённый), откуда, куда, когда, сколько мест, ребёнок до 7 лет (своё кресло / нужно кресло водителя), багаж (сумка / чемодан / много — 600 ₽ предоплатой водителю), комментарий.
- Гибкий поиск: нет точного рейса → показать ±2 часа и соседние дни.
- Нет рейсов → заявка водителям направления; не взяли за 30 минут → админу.
- Бронь за другого: заказчик + пассажир (имя, телефон, взрослый / подросток / ребёнок). Водитель видит обоих.
- Сохранённые адреса и пассажиры, кнопки «Повторить» и «Обратно» в «Мои поездки».
- Предоплата за крупный багаж: реквизиты только из анкеты водителя + предупреждение о мошенниках; водитель отмечает «Предоплата получена».

**Уведомления и правила**
- Бронь подтверждена, «Едете?» за 3 часа, статусы поездки, «Доехали».
- Статусы «Сел в машину» и «Доехали» — заказчику, если едет другой человек.
- Отмена: свободно больше чем за 4 часа, позже — «поздняя отмена» в истории. 3 поздние отмены или неявки за месяц → бронь только с подтверждением админа.

**Канал**
- Бот публикует и обновляет сводный пост «Рейсы на <день>» в канале направления.

**Админ — прямо в боте, без Mini App**
- Очередь проверки водителей: фото, данные, «Одобрить» / «Отклонить с причиной» / «Запросить фото заново».
- Заявки без водителя: подходящие водители, «Предложить водителю».
- Жалобы: список, статус, заметка, решение.
- Блокировка и ограничения пользователей, ручная выдача привилегий водителям (значок «Проверен», приоритет).
- Настройки в базе: лимиты, сроки (30 мин, 4 часа, 3 часа и т.д.) — без переделки кода.
- Уведомления админу о срочном.

## Что НЕ входит в версию 1

Mini App, расписание рейсов, лист ожидания, несколько пассажиров с разных адресов в одной брони, оценки, посылки, статистика, рассылки, монетизация, татарский язык, другие направления (но база и код — сразу под много направлений).

## Стек

- TypeScript, Node.js
- grammY (бот), conversations-плагин для пошаговых сценариев
- PostgreSQL + Drizzle ORM (миграции)
- Хостинг в российском облаке (Timeweb Cloud или Yandex Cloud), управляемый PostgreSQL. Персональные данные — только на серверах в РФ.
- Фото документов — S3-совместимое хранилище в РФ, доступ только админам.

## Правила для кода

- Все тексты бота — в отдельном файле `locales/ru` (или аналог), не в коде. Потом добавится татарский.
- Все числа-правила — в таблице `settings`, не в коде.
- Направления, города и деревни — данные в базе, не константы.
- Секреты (токен бота, пароль БД) — только в `.env`, в репозиторий не попадают; в репозитории `.env.example`.
- Отдельный тестовый бот и тестовая база для разработки.
- Время — с учётом часового пояса Europe/Moscow (Татарстан).
- Ошибки логируются; ежедневный бэкап базы.

## Порядок работы

Каждый этап заканчивается рабочим ботом, который можно потрогать в тестовом Telegram.

1. **Каркас:** репозиторий, grammY, PostgreSQL, Drizzle, `.env`, тестовый бот отвечает на `/start`, README с запуском.
2. **Регистрация и роли:** пассажир / водитель, телефон, анкета водителя, проверка админом.
3. **Рейсы водителя:** выложить, повторить, мои рейсы, места по телефону, защита от спама.
4. **Поиск и бронь:** анкета пассажира, гибкий поиск, бронь за другого, багаж и кресло, сохранённые адреса, заявки.
5. **Уведомления и статусы:** подтверждения, «Едете?», кнопки поездки, отмены и неявки.
6. **Канал:** сводный пост рейсов.
7. **Админ в боте:** заявки без водителя, жалобы, блокировки, привилегии, настройки.
8. **Пилот:** деплой в облако, бэкапы, логирование ошибок.
