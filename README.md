# Барам

Telegram-бот попутчиков Буинск ⇄ Казань. «Барам» по-татарски — «еду».

Версия 1 — чат-бот на одном направлении: пассажир находит рейс и бронирует место, водитель выкладывает рейсы и ведёт поездку кнопками, админ работает прямо в боте. Что входит в версию — в [docs/Старт разработки.md](docs/Старт%20разработки.md).

## Что нужно для запуска

- Node.js 22 или новее
- PostgreSQL 16 (для разработки — из `docker-compose.yml`)
- Токен бота от [@BotFather](https://t.me/BotFather). Для разработки заведите **отдельного тестового бота**.

## Запуск на своём компьютере

```bash
npm install
```

```bash
cp .env.example .env
```

Откройте `.env` и впишите `BOT_TOKEN`. Остальное можно оставить как есть.

```bash
docker compose up -d
```

```bash
npm run dev
```

Бот сам создаёт таблицы и заполняет начальные данные: направление Буинск ⇄ Казань и настройки. Напишите боту `/start`.

Чтобы стать админом, отправьте боту `/id`, впишите число в `ADMIN_IDS` в `.env` и перезапустите бота. Появится кнопка «🛠 Админ».

## Запуск на сервере

Пошаговая инструкция — в [docs/DEPLOY.md](docs/DEPLOY.md). Коротко:

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Поднимаются три контейнера: бот, PostgreSQL и ежедневный бэкап базы в папку `backups/`.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Бот с перезапуском при изменении кода |
| `npm test` | Тесты: сценарии кнопками на подменённом Telegram |
| `npm run typecheck` | Проверка типов |
| `npm run build` и `npm start` | Сборка и запуск собранного бота |
| `npm run db:generate` | Новая миграция после правки `src/db/schema.ts` |
| `python3 scripts/keys.py` | Сверка: у каждого текста в коде есть строка в `locales/ru.ftl` |

Тесты не требуют ни Telegram, ни Docker: база поднимается в памяти. Прогнать их на настоящем PostgreSQL:

```bash
TEST_DATABASE_URL=postgres://baram:baram@localhost:5432/baram_test npx vitest run --no-file-parallelism
```

## Как устроен код

```
src/
  index.ts            запуск: миграции, начальные данные, бот, фоновые задачи
  config.ts           чтение .env
  db/schema.ts        таблицы (Drizzle)
  services/           правила без Telegram: рейсы, брони, поиск, заявки, настройки
  bot/
    bot.ts            сборка бота и порядок обработчиков
    wizard.ts         вопрос-ответ с «Назад» и «В начало»
    conversations/    пошаговые сценарии: регистрация, анкета, рейс, поиск
    handlers/         кнопки меню и карточек: водитель, пассажир, заявки, админ
    actions.ts        действие = запись в базу + уведомления + пост в канале
    ui/               карточки рейса и брони, главное меню
  jobs/runner.ts      напоминания «Едете?», передача заявок админу, автозакрытие рейсов
locales/ru.ftl        все тексты бота
drizzle/              миграции базы
tests/                сценарные тесты
miniapp/design/       дизайн Mini App: токены, узоры, спецификация
```

## Правила, которые держит код

- **Тексты** — только в `locales/ru.ftl`. Татарский добавится файлом `tt.ftl`.
- **Числа-правила** (30 минут, 4 часа, лимиты) — в таблице `settings`, меняются в боте: Админ → Настройки.
- **Направления, города и деревни** — строки в базе. Деревни добавляет админ: Админ → Деревни.
- **Секреты** — только в `.env`, в репозиторий он не попадает.
- **Время** — в часовом поясе `APP_TZ` (по умолчанию Europe/Moscow).

## Что отложено

- Фото прав и СТС и проверка по ним: сейчас админ проверяет анкету и фото машины.
- Mini App, расписание рейсов, лист ожидания, оценки, посылки, монетизация — после версии 1.
